## Bounded first learning-curve schedule

| Setting | Proposed value |
| --- | --- |
| Maximum optimizer updates | 8,192, with a six-hour training wall-clock cap |
| Microbatch / accumulation | 1 / 8 on the existing single GPU |
| Seed / learning rate / warmup | 42 / 1e-4 / 0.05 |
| State dropout | 0.0 in processor and action head, audited at runtime |
| Tuning and augmentation | Preserve the validated follow-up recipe |
| Loader workers / shard size | 0 / 256 initially; determine shard coverage from the new training inventory |
| Model-only checkpoints | Steps 2,048, 4,096, 6,144, and 8,192; preserve all four |
| Run identity | A fresh larger-dataset identity, distinct from every pilot run |

At the measured approximately 1.6 seconds per update, 8,192 updates suggest about 3.6 hours of training, with the first saved checkpoint after roughly 55 minutes. This is a planning estimate: more episodes, data loading, checkpoint writes, and validation may change it. A 2,048-update run would supply only 16,384 microbatch examples, likely less than one pass through approximately 98 episodes. The proposed 8,192 updates supply 65,536 examples while keeping the same four-checkpoint storage budget; this reduces the chance of repeating an underexposed probe. Freeze the actual frame count and record sampled episode/frame coverage and effective passes: repeated samples are not unique coverage. This remains a bounded learning-curve experiment, not a full-fitting verdict. Stop on nonfinite losses/gradients, invalid data or provenance, resource reserves, or the fixed cap. Review the curves before proposing any extension; none is automatic.

Storage is a prerequisite. The host has roughly 16 GiB free in `/dev/shm` after the existing runs; the sandbox's empty shared-memory view is misleading. One measured model-only checkpoint is 12,583,367,834 bytes (11.72 GiB). Four such checkpoints plus the upstream final-root copy require about 62.92 GB (58.60 GiB), before logs, staging, or uncertainty. Provision a dedicated run volume with at least 80 GiB free, plus separately budgeted new snapshot/conversion space; retain an 8 GiB project reserve. Recheck at least 60 GiB available host RAM and 40 GiB free VRAM on the host, and monitor data-loading memory. The earlier 35 GiB single-final-checkpoint startup guard is insufficient for this schedule. No existing checkpoint, archive, dataset, or hard-linked original shard may be modified or removed to make room. Keep four checkpoints locally and durably archive each with checksum verification; any alternative rolling retention requires an explicit verified-archive policy before launch. Provisioning and archival transfer time are separate from the training estimate.
